# 测试流程

## 测试前准备

### 1. 同步Config文件
```powershell
.\sync_configs.ps1
```

### 2. 清理旧进程
```powershell
# 查找占用端口的进程
netstat -ano | findstr :6016

# 杀掉进程
taskkill /F /PID <PID>
```

### 3. 验证Config文件
```powershell
python test_config_loading.py
```

## 功能测试

### 1. Push-to-Talk模式
1. 启动应用: `cd frontend && npm run dev`
2. 设置录音模式为"对讲机模式"
3. 按住热键（默认RCtrl）
4. 说话："你好世试"
5. 松开热键
6. 验证：录音立即停止，文本显示正确

### 2. Toggle模式
1. 切换到"开关模式"
2. 按一次热键开始录音
3. 说话："这是开关模式测试"
4. 再按一次热键停止
5. 验证：录音停止，文本显示正确

### 3. 模型切换
1. 确保Paraformer正在运行
2. 点击Qwen3-ASR-0.6B卡片
3. 验证：状态变为"Loading"，切换完成后显示"Running"

### 4. 模型设置
1. 点击Qwen3的设置图标
2. 选择设备（如CUDA）
3. 选择语言（如English）
4. 点击"Apply Settings"
5. 验证：模型重新加载，设置生效

### 5. 热键配置
1. 进入设置页面
2. 点击"配置快捷键"
3. 按下新的快捷键
4. 保存并测试
5. 验证：新热键生效

## 压力测试

### 1. 快速连按测试
快速连续按下松开热键5次（间隔< 100ms），验证不会出现状态错误。

### 2. 长时间录音测试
Toggle模式下连续说话30秒，验证录音流畅，内存占用稳定。

### 3. 设备切换测试
在Settings中切换输入设备，测试录音功能是否正常。

## 边界测试

### 1. 空音频处理
按下热键立即松开（< 50ms），重复5次，验证系统不会崩溃。

### 2. 网络断开恢复
1. 开始录音
2. 停止后端
3. 观察UI状态
4. 重启后端
5. 验证：自动重连，录音功能恢复

### 3. Debug页面 - KeyUp/KeyDown测试

**测试目标**: 验证Debug页面正确显示KeyDown (⬇️) 和 KeyUp (⬆️) 事件。

**测试步骤**:
1. 启动开发服务器: `npm run dev`
2. 验证Debug标签出现在侧边栏（仅开发模式）
3. 导航到Debug页面
4. 点击"Start Recording Keys"按钮
5. 按住Right Ctrl键
6. 松开Right Ctrl键
7. 验证两个事件都出现在控制台

**预期结果**:
- Debug标签在开发模式下可见
- 控制台显示：
  - ⬇️ KeyDown事件（按下时）
  - ⬆️ KeyUp事件（松开时）
- 两个事件显示正确的键码和修饰键状态
- 事件清楚区分左右修饰键（如ControlLeft vs ControlRight）

**实现细节**:
- DebugPage.tsx中添加了KeyUp事件监听器
- 使用⬇️和⬆️图标进行视觉区分
- 事件显示：code, key, ctrl, alt, shift, meta状态
- 控制台保留最后20个事件

**注意**: 这验证了对讲机交互模式的核心功能。
