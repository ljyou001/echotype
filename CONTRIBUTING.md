# Contributing to EchoType

**为 EchoType 做贡献 / Contributing to EchoType**

Thank you for your interest in contributing to EchoType. Please read this guide first.

感谢你对 EchoType 的贡献。请先阅读本指南。

---

## Contributor License Agreement (CLA) / 贡献者许可协议

**Before submitting a Pull Request, please ensure you have agreed to the [Contributor License Agreement (CLA)](CLA.md).**

**在提交 Pull Request 之前，请确保你已同意 [Contributor License Agreement (CLA)](CLA.md)。**

- Submitting a PR indicates that you have read and agree to the CLA terms.
- 提交 PR 即表示你已阅读并同意 CLA 条款。

- If you are a **first-time contributor**, the CLA check in this repository will verify whether you are on the signed list. If not yet signed, please open an **Issue** with the title `[CLA] I agree to the Contributor License Agreement` and state that you have read and agree to [CLA.md](CLA.md). The maintainer will add your GitHub username to [.github/cla-signatures.txt](.github/cla-signatures.txt).
- 若你是**首次贡献者**，本仓库的 CLA 检查会验证你是否已被列入已签署名单。若尚未签署，请开一个 **Issue**，标题为：`[CLA] I agree to the Contributor License Agreement`，并说明你已阅读并同意 [CLA.md](CLA.md)。维护者会将你的 GitHub 用户名加入 [.github/cla-signatures.txt](.github/cla-signatures.txt)。

- **Major contributors**: If your contribution is very substantial (e.g. long-term core contribution or a major feature/module), you may contact the maintainer to discuss different terms (e.g. license grant instead of copyright assignment, or joint copyright). See [CLA.md](CLA.md) Section 2.3.
- **重大贡献者**：若你的贡献量非常大（例如长期核心贡献或主要功能/模块），可联系维护者协商不同条款（如许可授予而非版权转让、共同著作权等）。详见 [CLA.md](CLA.md) 第 2.3 节。

## How to Contribute / 如何贡献

1. Fork this repository. / Fork 本仓库。
2. Create a branch: `git checkout -b feature/your-feature` or `fix/your-fix`. / 创建分支：`git checkout -b feature/your-feature` 或 `fix/your-fix`。
3. Make your changes and run tests. / 修改代码并测试。
4. Commit and push to your fork. / 提交并推送到你的 fork。
5. Open a Pull Request and fill in the PR template (if any). / 打开 Pull Request，并填写 PR 模板（如有）。
6. Wait for the CLA check to pass and for code review. / 等待 CLA 检查通过及 Code Review。

---

## Code Style & Conventions / 代码风格与约定

- **Backend (Python)**: Follow the project’s existing style; we recommend formatting with `black` / `ruff`.  
- **后端（Python）**：遵循项目现有风格，建议使用 `black` / `ruff` 格式化。

- **Frontend (TypeScript/React)**: Follow the project’s existing style; run `npm run build` before submitting to ensure it passes.  
- **前端（TypeScript/React）**：遵循项目现有风格，提交前运行 `npm run build` 确保通过。
